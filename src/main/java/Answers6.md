# Задание 1. Сортировка и детерминизм

## Теория
- **Детерминизм** — это когда при одинаковом наборе данных программа всегда выдает одинаковый результат, независимо от того, в каком порядке данные поступили изначально.
- В Stream API сортировка делается через `.sorted(Comparator)`.
- Если главные поля совпадают (например, одинаковый `level`), порядок может зависеть от исходного списка. Чтобы этого избежать, используются **tie-breakers** (дополнительные условия): `.thenComparing(...)`.

### Демонстрация
Вывод программы:
```
=== Задание 1: Сортировка и детерминизм ===
Отсортированный список 1:
Course[id=2, code=JAVA-1, level=A, duration=32]
Course[id=3, code=WEB-1, level=A, duration=32]
Course[id=4, code=SQL-1, level=B, duration=20]
Course[id=1, code=JAVA-2, level=B, duration=40]

Отсортированный список 2:
Course[id=2, code=JAVA-1, level=A, duration=32]
Course[id=3, code=WEB-1, level=A, duration=32]
Course[id=4, code=SQL-1, level=B, duration=20]
Course[id=1, code=JAVA-2, level=B, duration=40]

Результаты идентичны: true
```
Объяснение вывода: Оба списка были отсортированы по `level`, затем по `duration`, затем по `code`. Курсы `JAVA-1` и `WEB-1` имеют одинаковый level "A" и duration 32, поэтому они отсортировались по коду (JAVA-1 идет раньше WEB-1). Результаты полностью идентичны.

#### Правило
При сортировке коллекций объектов всегда указывайте все поля, которые однозначно определяют порядок (tie-breakers), чтобы избежать случайной нестабильной сортировки.

# Задание 2. flatMap

## Теория
- Метод `map()` преобразует один элемент в другой (1 к 1).
- Метод `flatMap()` преобразует один элемент в **поток** элементов (1 к N) и затем объединяет (выравнивает) все эти потоки в один общий. Идеально подходит, когда у объекта есть вложенный список.
- **Обратный индекс** — это структура `Map<Key, List<Value>>`, которая позволяет по ключу быстро найти все связанные объекты.
- Нормализация строк (например, `trim().toLowerCase()`) нужна, чтобы `"Java"` и `" java "` считались одной и той же темой.

### Демонстрация
Вывод программы:
```
=== Задание 2: flatMap и обратный индекс ===
Обратный индекс тем:
Тема: 'databases'
  - SQL-1
Тема: 'oop'
  - JAVA-1
Тема: 'java'
  - JAVA-1
  - JAVA-2
Тема: 'streams'
  - JAVA-2
Тема: 'sql'
  - SQL-1
```
Объяснение вывода: Курсы `JAVA-1` и `JAVA-2` имели темы `"Java"` и `" java "`. Благодаря нормализации они обе превратились в `"java"` и попали в один список. Вложенные списки модулей были развернуты с помощью `flatMap` и сгруппированы в `Map`.

#### Правило
Используйте `flatMap`, когда вам нужно превратить `Stream<List<T>>` в `Stream<T>` или когда каждый элемент порождает несколько других элементов.

# Задание 3. reduce с правильной identity

## Теория
- Метод `reduce` сворачивает весь поток в один результат. Он принимает **identity** (начальное значение) и **accumulator** (функцию объединения).
- **Правильная identity** должна быть нейтральным элементом (для суммы это `0`, для умножения `1`, для строк `""`). Прибавление правильной identity не меняет результат.
- **Неправильная identity** искажает результат. Если для суммы использовать `1000`, итоговая сумма будет завышена на 1000.
- **Ассоциативность accumulator** означает, что порядок применения операции не важен: `(a + b) + c == a + (b + c)`. Это критически важно для корректной работы в параллельных потоках.

### Демонстрация
Вывод программы:
```
=== Задание 3: reduce с правильной identity ===
Правильная сумма (identity = 0): 92
Неправильная сумма (identity = 1000): 1092
Ассоциативность: true
```
Объяснение вывода: С правильной identity (0) сумма длительностей трех курсов равна 92. С неправильной identity (1000) она равна 1092, так как 1000 прибавилась к итогу. Ассоциативность суммы подтверждена.

#### Правило
Всегда используйте нейтральную identity для `reduce`, чтобы не искажать результат, и убедитесь, что accumulator ассоциативен для безопасного использования в параллельных потоках.

# Задание 4. Collectors

## Теория
- **Collectors** — это готовые стратегии для сбора элементов потока (например, `groupingBy`, `counting`, `averagingInt`).
- Если делать `stream().collect(groupingBy(...))` несколько раз подряд, программа будет делать несколько полных проходов по данным. Это неэффективно.
- **`teeing`** (Java 12+) позволяет за **один проход** собрать два разных результата (например, количество и среднюю длительность) и объединить их в один объект через функцию-мержер.
- **Summary object** — это специальный класс (или `record`), который хранит агрегированные данные (например, `LevelSummary(count, averageDuration)`).

### Демонстрация
Вывод программы:
```
=== Задание 4: Collectors и summary object ===
Сводка по уровням:
  Level A: count=2, avgDuration=26.0
  Level B: count=2, avgDuration=30.0
```
Объяснение вывода: Стрим сгруппировал курсы по уровню. Для каждого уровня через `teeing` были собраны: количество (`counting`) и средняя длительность (`averagingInt`). Затем эти два значения были переданы в конструктор `LevelSummary`. Для уровня A: 2 курса, средняя длительность (32+20)/2 = 26.0.

#### Правило
Используйте `teeing`, если вам нужно извлечь несколько независимых агрегаций (count, sum, avg) за один проход по коллекции. Это экономит ресурсы процессора.

# Задание 5. Optional как результат

## Теория
- **`Optional`** — это контейнер, который может содержать значение, а может быть пустым. Он используется для возврата из методов, чтобы избежать `NullPointerException`.
- Метод **`max()`** возвращает `Optional<T>`, так как коллекция может оказаться пустой.
- **`Optional.get()`** без предварительной проверки — плохая практика. Вместо этого используют:
  - `orElse(defaultValue)` — вернуть значение или дефолтное.
  - `orElseThrow()` — выбросить исключение, если пусто.
  - `map()` — преобразовать значение, если оно есть.
- **Нельзя хранить `Optional` в полях класса** (это увеличивает память и нарушает сериализацию). Он предназначен только для возврата из методов.

### Демонстрация
Вывод программы:
```
=== Задание 5: Optional как результат ===
1. Поиск самого длинного курса (есть данные):
  Самый длинный: JAVA-2 (40h)

2. Поиск самого длинного курса (пустой список):
  Результат: Нет курсов
```
Объяснение вывода: В первом случае `max()` нашел курс длительностью 40 часов, мы преобразовали его код и длительность через `map()`. Во втором случае список был пуст, `max()` вернул пустой `Optional`, и сработал `orElse("Нет курсов")`.

#### Правило
Возвращайте `Optional` из методов, которые могут ничего не найти. Используйте `map` для трансформации и `orElse` для безопасного извлечения значения.

# Задание 6. Собственный collector

## Теория
- **`Collector`** состоит из 4 функций:
  1. **Supplier** — создает новый контейнер для хранения промежуточного результата.
  2. **Accumulator** — добавляет элемент в контейнер.
  3. **Combiner** — объединяет два контейнера (нужно для параллельных потоков).
  4. **Finisher** — превращает контейнер в итоговый неизменяемый объект (у нас это `record`).
- **`Collectors.summarizingInt()`** — готовый коллектор, который сразу возвращает `IntSummaryStatistics` (count, sum, min, max, average).
- Собственный коллектор позволяет контролировать процесс сбора данных и возвращать любой удобный тип (например, свой `record`).

### Демонстрация
Вывод программы:
```
=== Задание 6: Собственный collector ===
1. Собственный коллектор:
  DurationStats[count=3, sum=92, min=20, max=40]

2. Готовый summarizingInt:
  IntSummaryStatistics{count=3, sum=92, min=20, average=30.666667, max=40}
```
Объяснение вывода: Наш коллектор и стандартный `summarizingInt` собрали одинаковую статистику: 3 курса, суммарная длительность 92, минимум 20, максимум 40.

#### Правило
Собственный коллектор создается через `Collector.of()`. Важно использовать неизменяемые контейнеры (или `record`) на этапе `finisher`, чтобы избежать случайного изменения результата.
