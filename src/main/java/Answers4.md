# Задача 1. String: identity и value

## Теория
- В Java строки неизменяемы. Оператор `==` сравнивает ссылки (адреса в памяти), а метод `equals` сравнивает сами символы.
- Конкатенация - это склеивание строк через знак `+`. Если склеиваются строки в кавычках (литералы), компилятор делает это сразу при сборке программы (compile-time). Если склеиваются переменные, склеивание происходит во время работы программы (runtime), и создается новый объект в памяти.
- String Pool (пул строк) - это специальный склад строк в памяти. Когда мы пишем строку в кавычках, Java проверяет, есть ли такая на складе. Если есть, возвращает ссылку на нее, чтобы не тратить память.
- Метод `intern()` позволяет принудительно положить строку на этот склад (или найти уже существующую там) и получить ссылку на нее.

### Демонстрация
Вывод программы:
```
=== 1. Литералы и == ===
s1 == s2: true
s1.equals(s2): true

=== 2. new String ===
s1 == s3: false
s1.equals(s3): true

=== 3. Конкатенация compile-time ===
s1 == s4: true
s1.equals(s4): true

=== 4. Конкатенация runtime ===
s1 == s5: false
s1.equals(s5): true

=== 5. intern ===
s1 == s6: true
```
Объяснение вывода:
1. Литералы: обе строки ищутся в пуле, находят одну и ту же, поэтому ссылки одинаковые (`true`).
2. `new String`: принудительно создает новый объект в куче, адрес другой (`false`), но символы те же (`equals` дает `true`).
3. Compile-time конкатенация: компилятор склеивает константы "Ja" и "va" прямо в коде в одну строку "Java", которая попадает в пул, поэтому `==` дает `true`.
4. Runtime конкатенация: склейка переменных создает новый объект в куче, адрес другой (`false`).
5. `intern`: переносит строку из кучи в пул и возвращает ссылку на пуловский вариант, поэтому `==` с изначальным литералом дает `true`.

#### Правило
Текст в Java сравнивается только через `equals()` (или `Objects.equals()` для защиты от null). Оператор `==` для строк использовать нельзя, кроме проверки на null.

# Задача 2. Сборка строки

## Теория
- В Java строки неизменяемы (immutable). Если мы "меняем" строку, на самом деле каждый раз создается абсолютно новый объект в памяти. Старый объект становится мусором.
- Конкатенация через `+` в цикле работает очень медленно, потому что на каждой итерации создается новая строка, куда перекопируется все предыдущее содержимое. Чем длиннее строка, тем дольше копирование.
- `StringBuilder` - это изменяемый буфер. Он хранит массив символов. При добавлении текста (`append`) он просто дописывает символы в конец массива. Когда буфер заполняется, он расширяется. В конце мы вызываем `toString()`, и создается одна итоговая строка.
- Разница в скорости становится огромной при больших объемах данных.

### Демонстрация
Вывод программы:
```
=== Сборка через + ===
Время: 163 мс
Длина строки: 98890

=== Сборка через StringBuilder ===
Время: 1 мс
Длина строки: 98890

Результаты идентичны: true
```
Объяснение вывода:
1. Сборка через `+` заняла 163 мс, потому что на каждой из 10000 итераций создавалась новая строка и копировались все предыдущие символы.
2. Сборка через `StringBuilder` заняла 1 мс, потому что символы просто добавлялись в конец внутреннего массива без пересоздания объекта.
3. Обе строки получились одинаковой длины (98890) и идентичны по содержанию (`equals` дает `true`), разница только в затраченном времени.

#### Правило
Для сборки или изменения строк в цикле (или при множественных операциях) всегда используется `StringBuilder`. Оператор `+` подходит только для простых склеек в одну строку (например, `String s = a + b;`).

# Задача 3. Регулярное выражение с группами

## Теория
- Регулярные выражения в Java используются для проверки строк по шаблону. Главные классы: `Pattern` (компилирует шаблон) и `Matcher` (применяет его к строке).
- Круглые скобки `()` в регулярном выражении создают группы. Это позволяет потом извлечь нужные части строки отдельно (например, префикс и число).
- Метод `matches()` проверяет, совпадает ли шаблон со строкой целиком от начала до конца. Это защищает от частичных совпадений (когда в строке есть лишние символы до или после).
- Шаблон `[A-Z]{2,4}` ищет от 2 до 4 заглавных латинских букв. Пробелы, кириллица и строчные буквы под этот шаблон не подходят.
- `\d{3}` ищет ровно три цифры.

### Демонстрация
Вывод программы:
```
=== Валидные коды ===
OK: "JAVA-101" -> prefix=JAVA, number=101
OK: "CS-999" -> prefix=CS, number=999
OK: "WEB-001" -> prefix=WEB, number=001

=== Невалидные коды ===
FAIL: "java-101" (невалидный)
FAIL: "JAVA101" (невалидный)
FAIL: "JAVA-10" (невалидный)
FAIL: "JAVA-101!" (невалидный)
FAIL: " JAVA-101" (невалидный)
FAIL: "JAVA-101 " (невалидный)
FAIL: "ПРОГ-101" (невалидный)
FAIL: "TOOLONG-101" (невалидный)
```
Объяснение вывода:
1. Валидные коды (`JAVA-101`, `CS-999`, `WEB-001`) полностью соответствуют шаблону. `Matcher.matches()` возвращает `true`, а через `matcher.group(1)` и `matcher.group(2)` извлекаются префикс и число.
2. Строчные буквы (`java-101`) не подходят под `[A-Z]`, так как шаблон требует заглавные.
3. Отсутствие дефиса (`JAVA101`) или недостаточное количество цифр (`JAVA-10`) нарушают структуру.
4. Лишние символы (`JAVA-101!`) или пробелы (` JAVA-101`) приводят к тому, что `matches()` возвращает `false`, потому что строка не совпадает целиком.
5. Кириллица (`ПРОГ-101`) и слишком длинный префикс (`TOOLONG-101`) не проходят из-за строгого ограничения `{2,4}` и диапазона `A-Z`.

#### Правило
Для строгой проверки формата строки всегда используется `matches()` (или добавляются якоря `^` и `$` при использовании `find()`). Группы `()` позволяют удобно извлекать части данных из валидной строки.
