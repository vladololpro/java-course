## Задание 1. Сортировка и детерминизм

### Условие
Отсортируйте курсы по `level`, `duration` и `code` с явными tie-breakers. Результат должен быть одинаковым для разных исходных порядков, если множество данных одинаково.

### Теория
- **Детерминизм** — одинаковые входные данные дают одинаковый результат независимо от исходного порядка элементов.
- `Stream.sorted(Comparator)` — промежуточная операция; она не запускает обработку сразу. Сортировка выполняется при вызове терминальной операции, например `toList()` или `collect()`.
- **Tie-breaker** — дополнительное условие сравнения, которое применяется, когда основные поля совпали.
- `Comparator.comparing(...).thenComparing(...)` строит цепочку сравнений: следующее условие используется только при равенстве предыдущих.
- Сортировка в Java **стабильная**: элементы с равными ключами сохраняют относительный исходный порядок. Поэтому без полного набора tie-breakers результат может зависеть от входного порядка.
- Уникальный `id` в конце цепочки делает порядок однозначным, если `id` действительно уникален.
- Для числовых полей лучше `comparingInt`/`thenComparingInt`, а не вычитание `a - b`: вычитание может переполниться.

### Объяснение кода
- `CourseSorter` хранит готовый `static final Comparator<Course> COURSE_COMPARATOR`.
- Порядок сравнения:
  1. `level`;
  2. `duration`;
  3. `code`;
  4. `id` — финальный уникальный tie-breaker.
- `sortCourses` не меняет исходный список: создаёт stream, сортирует и возвращает новый неизменяемый список через `toList()`.
- В `demo` два списка содержат одни и те же курсы в разном порядке. После сортировки списки равны, потому что все значимые поля и `id` входят в компаратор.
- Совпадение `level` и `duration` у `JAVA-1` и `WEB-1` разрешается по `code`.

**Подробнее по шагам.**
1. Компаратор сравнивает `level` как `String` в естественном порядке.
2. Если `level` одинаковый, сравнивается `duration`.
3. Если и длительность одинаковая, сравнивается `code`.
4. Если совпали все три поля, сравнивается `id` через `thenComparingLong`.
5. `sorted` применяет компаратор ко всем элементам потока.
6. `toList()` собирает результат в новый список.
7. Два разных входных порядка дают одинаковый выходной порядок, потому что `id` уникален.

**Почему это детерминизм.** Стабильная сортировка сама по себе не делает порядок независимым от входа: равные элементы останутся в том порядке, в котором пришли. Уникальный финальный ключ устраняет эту неопределённость.

### Что могут спросить и как отвечать
**Что такое детерминированная сортировка?**
Это сортировка, результат которой зависит только от множества элементов и компаратора, но не от того, в каком порядке элементы пришли на вход.

**Зачем нужны tie-breakers?**
Когда основные ключи равны, без дополнительного условия сохраняется исходный порядок равных элементов. Разный вход может дать разный выход.

**Почему последним стоит `id`?**
`id` предполагается уникальным. Если все предыдущие поля совпали, `id` всё равно даст однозначный порядок.

**Что будет, если `id` не уникален?**
Для полностью одинаковых по компаратору элементов порядок снова может зависеть от входа. Тогда нужен ещё один уникальный ключ или нужно считать такие элементы неразличимыми.

**`Stream.sorted` стабилен?**
Для упорядоченного потока — да, сортировка стабильная. Но полагаться только на стабильность для детерминизма нельзя: она сохраняет входной порядок равных элементов.

**Почему не сравнивать через `duration1 - duration2`?**
Разность `int` может переполниться. Безопаснее `Comparator.comparingInt(...)` или `Integer.compare(...)`.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/CourseSorter.java`.

```java
private static final Comparator<Course> COURSE_COMPARATOR =   // 1
        Comparator.comparing(Course::level)                    // 2
                .thenComparing(Course::duration)               // 3
                .thenComparing(Course::code)                   // 4
                .thenComparingLong(Course::id);                // 5

public List<Course> sortCourses(List<Course> courses) {       // 6
    return courses.stream()                                   // 7
            .sorted(COURSE_COMPARATOR)                         // 8
            .toList();                                         // 9
}                                                             // 10

List<Course> sorted1 = sortCourses(list1);                    // 11
List<Course> sorted2 = sortCourses(list2);                    // 12
System.out.println("Результаты идентичны: "                  // 13
        + sorted1.equals(sorted2));                           // 14
```

1. `static final` — компаратор один на класс, создаётся один раз и не меняется.
2. `comparing(Course::level)` — первое условие: уровень курса.
3. `thenComparing(Course::duration)` — применяется только при равных уровнях.
4. `thenComparing(Course::code)` — разрешает совпадение уровня и длительности.
5. `thenComparingLong(Course::id)` — финальный уникальный tie-breaker.
6. `sortCourses` принимает список и возвращает новый список.
7. `courses.stream()` — создаёт поток без изменения исходного списка.
8. `sorted(...)` — сортирует элементы по цепочке компараторов.
9. `toList()` — терминальная операция, собирает результат в неизменяемый список.
10. `}` — исходный `courses` не мутируется.
11. Первый список сортируется в отдельный результат.
12. Второй список с другим входным порядком сортируется независимо.
13. Печатается проверка равенства двух результатов.
14. `List.equals` сравнивает элементы по порядку и по `equals`; у `record Course` равенство учитывает все поля.

## Задание 2. `flatMap`

### Условие
Из курсов со списком модулей получите уникальные нормализованные темы и обратный индекс `topic → courses`. Не создавайте вложенный список вручную.

### Теория
- `map` преобразует один элемент в один результат: `1 → 1`.
- `flatMap` преобразует один элемент в поток результатов и выравнивает все потоки в один: `1 → N`.
- `Stream<List<T>>` после `flatMap` превращается в `Stream<T>`.
- **Обратный индекс** — `Map<Key, List<Value>>`, где по ключу (теме) можно быстро получить все связанные объекты (курсы).
- **Нормализация** приводит разные написания к одному виду: `" Java "` и `"java"` становятся одной темой.
- `Locale.ROOT` в `toLowerCase` делает регистронезависимое преобразование предсказуемым и не зависящим от локали машины.
- `distinct()` после нормализации убирает повторы тем внутри одного курса.
- `TreeMap::new` в `groupingBy` задаёт детерминированный порядок ключей в выводе.

### Объяснение кода
- `TopicIndexer.buildTopicIndex` для каждого курса разворачивает список `modules()`.
- Каждая тема нормализуется через `trim().toLowerCase(Locale.ROOT)`, затем `distinct()` убирает повторы внутри одного курса.
- После этого тема превращается в пару `Map.entry(topic, course)`.
- `flatMap` выравнивает потоки тем всех курсов в один поток пар.
- `groupingBy` группирует пары по теме и явно использует `TreeMap::new`.
- `mapping(Map.Entry::getValue, toList())` оставляет в значении только курс, отбрасывая ключ темы.
- В результате получается `Map<String, List<Course>>` с отсортированными ключами.
- `normalize` делает `trim()` и `toLowerCase(Locale.ROOT)`.

**Подробнее по шагам.**
1. Для курса `JAVA-1` список модулей `["Java", "OOP"]`.
2. `modules().stream()` даёт поток тем этого курса.
3. `map(this::normalize)` приводит темы к одному виду.
4. `distinct()` удаляет повторы внутри курса, например `"Java"` и `" java "`.
5. Следующий `map` превращает тему в пару «нормализованная тема — курс».
6. `flatMap` объединяет пары всех курсов в один поток.
7. `groupingBy` собирает пары с одинаковым ключом в группы и создаёт `TreeMap`.
8. `mapping` преобразует группу пар в список курсов.
9. `" java "` и `"Java"` после нормализации попадают в один ключ `"java"`.

**Про уникальность.** Уникальны ключи итоговой `Map`: одна тема встречается в индексе один раз. `distinct()` дополнительно гарантирует, что один и тот же курс не попадёт в список темы дважды, если тема повторена в модулях курса.

**Про порядок вывода.** `Collectors.groupingBy` без явной `Map`-фабрики создаёт `HashMap`, где порядок ключей не гарантирован. В коде указан `TreeMap::new`, поэтому темы выводятся в алфавитном порядке и результат стабилен.

### Что могут спросить и как отвечать
**Чем `map` отличается от `flatMap`?**
`map` возвращает одно значение на входной элемент, `flatMap` — поток значений и затем выравнивает их. Для вложенных списков нужен `flatMap`.

**Почему не двумя вложенными циклами?**
Можно, но `flatMap` явно выражает преобразование «курс → много тем» и не требует ручного создания и заполнения промежуточного списка.

**Зачем `Map.entry`?**
Это промежуточная пара «тема — курс», которую удобно группировать по ключу, а затем извлекать значение. Она не создаёт вложенный список вручную.

**Зачем нормализация?**
Чтобы `"Java"`, `" java "` и `"JAVA"` считались одной темой, а не тремя разными ключами.

**Почему `Locale.ROOT`?**
Чтобы регистр преобразовывался одинаково на любой машине, независимо от системной локали.

**Гарантирован ли порядок ключей в результате?**
Да: в `groupingBy` явно передан `TreeMap::new`, поэтому ключи отсортированы. Без явной фабрики был бы `HashMap` с не гарантированным порядком.

**Как убрать дубликаты тем внутри одного курса?**
Нормализовать темы через `map(this::normalize)`, затем вызвать `distinct()` до создания пар «тема — курс».

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/TopicIndexer.java`.

```java
public Map<String, List<Course>> buildTopicIndex(List<Course> courses) { // 1
    return courses.stream()                                              // 2
            .flatMap(course -> course.modules().stream()                 // 3
                    .map(this::normalize)                                // 4
                    .distinct()                                          // 5
                    .map(topic -> Map.entry(topic, course)))             // 6
            .collect(Collectors.groupingBy(                              // 7
                    Map.Entry::getKey,                                   // 8
                    TreeMap::new,                                        // 9
                    Collectors.mapping(Map.Entry::getValue,              // 10
                            Collectors.toList())                         // 11
            ));                                                          // 12
}                                                                        // 13

private String normalize(String topic) {                                 // 14
    return topic.trim().toLowerCase(Locale.ROOT);                        // 15
}                                                                        // 16
```

1. Метод возвращает обратный индекс «тема → список курсов».
2. Поток исходных курсов.
3. `flatMap` для каждого курса открывает поток его модулей.
4. `map(this::normalize)` приводит тему к единому виду.
5. `distinct()` убирает повторы внутри одного курса.
6. Каждая оставшаяся тема превращается в пару `тема → курс`.
7. `groupingBy` собирает пары в `Map` по ключу.
8. Ключ группы — нормализованная тема.
9. `TreeMap::new` задаёт детерминированный порядок ключей.
10. Значение группы — результат `mapping`: из пары берётся только курс.
11. `toList()` собирает курсы группы в список.
12. `)` завершает `collect`; получается `Map<String, List<Course>>`.
13. `}` — исходные курсы и их модули не изменяются.
14. `normalize` — отдельная функция нормализации темы.
15. `trim()` убирает пробелы по краям, `toLowerCase(Locale.ROOT)` приводит к нижнему регистру.
16. `}` — конец `normalize`; результат используется как ключ группировки.

## Задание 3. `reduce` с правильной identity

### Условие
Посчитайте сумму длительностей и объедините value objects. Покажите неправильную identity, нарушающую результат, и сформулируйте ассоциативность accumulator.

### Теория
- `reduce` сворачивает поток в одно значение.
- **Identity** — начальное значение, нейтральное для операции:
  - для суммы — `0`;
  - для умножения — `1`;
  - для конкатенации строк — `""`.
- Нейтральность означает: `identity ⊕ x == x` и `x ⊕ identity == x`.
- **Accumulator** — функция, которая объединяет текущий результат со следующим элементом.
- **Ассоциативность**: `(a ⊕ b) ⊕ c == a ⊕ (b ⊕ c)`. Порядок группировки не должен менять результат.
- В параллельном потоке данные разбиваются на части. Каждая часть сворачивается отдельно, затем части объединяются. Ненейтральная identity может примениться несколько раз, а неассоциативная операция даст результат, зависящий от разбиения.
- Двухаргументный `reduce(identity, accumulator)` для параллельного потока тоже требует нейтральной identity и ассоциативного accumulator.

### Объяснение кода
- `sumDurations` преобразует курсы в `duration` и вызывает `reduce(0, Integer::sum)`.
- `joinCourseCodes` преобразует курсы в коды и вызывает `reduce("", DurationReducer::joinCodes)`.
- `joinCodes` обрабатывает пустые строки как отсутствие элемента и соединяет непустые коды через `", "`.
- В `demo` показаны:
  - правильная сумма `92`;
  - неправильная сумма с identity `1000` — `1092`;
  - правильное объединение кодов с identity `""`;
  - неправильное объединение с identity `"JAVA-1"` — лишний `JAVA-1`;
  - проверка ассоциативности `joinCodes`.

**Подробнее по шагам.**
1. Для суммы поток преобразуется в `Stream<Integer>` длительностей.
2. `reduce(0, Integer::sum)` начинает с `0` и последовательно прибавляет длительности.
3. `0` не меняет сумму, поэтому результат корректен.
4. Для строк поток преобразуется в коды курсов.
5. `reduce("", joinCodes)` начинает с пустой строки.
6. `joinCodes` возвращает второй элемент, если первый пуст, и первый, если пуст второй.
7. Поэтому пустая identity не добавляет лишний код.
8. С identity `"JAVA-1"` первый код оказывается добавлен дважды: как начальное значение и как элемент потока.
9. Ассоциативность проверяется двумя способами группировки трёх кодов; результаты совпадают.

**Почему identity важна.** В последовательном потоке неправильная identity хотя бы один раз искажает результат. В параллельном потоке она может добавиться к каждой части, поэтому ошибка становится ещё заметнее и зависит от разбиения.

### Что могут спросить и как отвечать
**Что такое identity в `reduce`?**
Начальное нейтральное значение. Для суммы это `0`, для строк — `""`. Оно не должно менять результат операции.

**Почему `1000` — неправильная identity для суммы?**
Потому что `1000` не нейтральна: она прибавляется к общей сумме и завышает результат.

**Почему `"JAVA-1"` — неправильная identity для объединения?**
Потому что это не пустая строка. Она попадает в результат как дополнительный элемент, даже если такого кода нет во входных данных.

**Что значит ассоциативность accumulator?**
Что результат не зависит от порядка группировки: `(a ⊕ b) ⊕ c` совпадает с `a ⊕ (b ⊕ c)`.

**Зачем ассоциативность, если поток последовательный?**
Для последовательного потока она тоже полезна для предсказуемости, но критична для параллельного: части сворачиваются независимо и затем объединяются.

**Почему `joinCodes` проверяет пустые строки?**
Чтобы пустая identity не превращалась в лишний элемент и чтобы объединение пустого результата с первым кодом давало просто код.

**Можно ли использовать `reduce` без identity?**
Да, есть перегрузка `reduce(BinaryOperator)`, возвращающая `Optional`. Но тогда пустой поток даёт `Optional.empty()`, а не начальное значение.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/DurationReducer.java`.

```java
public int sumDurations(List<Course> courses) {          // 1
    return courses.stream()                              // 2
            .map(Course::duration)                       // 3
            .reduce(0, Integer::sum);                    // 4
}                                                        // 5

public String joinCourseCodes(List<Course> courses) {   // 6
    return courses.stream()                              // 7
            .map(Course::code)                           // 8
            .reduce("", DurationReducer::joinCodes);     // 9
}                                                        // 10

static String joinCodes(String left, String right) {     // 11
    if (left.isEmpty()) {                                // 12
        return right;                                    // 13
    }                                                    // 14
    if (right.isEmpty()) {                               // 15
        return left;                                     // 16
    }                                                    // 17
    return left + ", " + right;                          // 18
}                                                        // 19

String part1 = joinCodes(joinCodes("JAVA-1", "JAVA-2"), "SQL-1"); // 20
String part2 = joinCodes("JAVA-1", joinCodes("JAVA-2", "SQL-1")); // 21
boolean associative = part1.equals(part2);                        // 22
```

1. `sumDurations` возвращает сумму длительностей.
2. Поток курсов.
3. `map(Course::duration)` оставляет только числа.
4. `reduce(0, Integer::sum)` — identity `0`, accumulator — сложение.
5. `}` — сумма собрана в `int`.
6. `joinCourseCodes` возвращает строку с кодами.
7. Поток курсов.
8. `map(Course::code)` оставляет только коды.
9. `reduce("", ...)` — identity пустая строка, accumulator — `joinCodes`.
10. `}` — строка собрана.
11. `joinCodes` объединяет два промежуточных значения.
12. Если слева пусто, это identity или пустая часть.
13. Возвращается правая часть без добавления разделителя.
14. `}` — конец первой проверки.
15. Если справа пусто, возвращается левая часть.
16. Возвращается левая часть без добавления разделителя.
17. `}` — конец второй проверки.
18. Оба значения непустые: соединяются через `", "`.
19. `}` — конец accumulator.
20. Левая группировка: сначала `JAVA-1` и `JAVA-2`, затем результат с `SQL-1`.
21. Правая группировка: сначала `JAVA-2` и `SQL-1`, затем `JAVA-1` с результатом.
22. `part1.equals(part2)` истинно — для этих данных accumulator ассоциативен.

## Задание 4. Collectors

### Условие
Сгруппируйте курсы по `level`, посчитайте количество и среднюю длительность, соберите summary object. Не выполняйте три полных прохода без объяснения.

### Теория
- **Collector** описывает, как собрать элементы потока в итоговую структуру.
- `Collectors.groupingBy(classifier, downstream)` группирует элементы по ключу и применяет к каждой группе downstream-коллектор.
- `Collectors.counting()` считает количество элементов в группе.
- `Collectors.averagingInt(...)` считает среднее арифметическое по `int`-полю.
- `Collectors.teeing(...)` (Java 12+) выполняет два downstream-коллектора за один проход и объединяет их результаты функцией.
- **Summary object** — объект, который хранит несколько агрегатов вместе. В проекте это `record LevelSummary(long count, double averageDuration)`.
- `teeing` не делает отдельный проход по каждой агрегации: элементы потока обрабатываются один раз, а результаты двух коллекторов объединяются.

### Объяснение кода
- `LevelSummarizer.summarize` вызывает `groupingBy(Course::level, teeing(...))`.
- Внутри `teeing`:
  - `counting()` считает курсы;
  - `averagingInt(Course::duration)` считает среднюю длительность;
  - `LevelSummary::new` объединяет два результата в summary object.
- Для уровня `A`: курсы `JAVA-1` (32) и `SQL-1` (20), count = 2, average = 26.0.
- Для уровня `B`: `JAVA-2` (40) и `WEB-1` (20), count = 2, average = 30.0.
- `groupingBy` создаёт `Map<String, LevelSummary>`.

**Подробнее по шагам.**
1. Поток курсов проходит `collect`.
2. `groupingBy` определяет группу по `level`.
3. Для каждой группы запускается `teeing`.
4. Первый downstream `counting()` считает количество элементов.
5. Второй downstream `averagingInt` суммирует длительности и делит на количество.
6. Оба результата передаются в конструктор `LevelSummary`.
7. В `Map` для каждого уровня сохраняется готовый summary object.
8. Пустой вход даёт пустую `Map`: групп нет, поэтому нет и summary.

**Почему не три прохода.** Можно было бы отдельно вызвать `groupingBy(counting())`, потом `groupingBy(averagingInt(...))` и затем объединить результаты. Это три обхода исходного потока. `teeing` собирает count и average в одном проходе по каждой группе.

### Что могут спросить и как отвечать
**Что делает `groupingBy`?**
Группирует элементы по ключу классификатора и применяет downstream-коллектор к каждой группе.

**Что такое `teeing`?**
Коллектор, который запускает два downstream-коллектора за один проход и объединяет их результаты заданной функцией.

**Почему `averagingInt` возвращает `double`?**
Среднее может быть дробным, даже если исходные значения целые. Поэтому результат имеет тип `double`.

**Зачем summary object?**
Чтобы вернуть count и average вместе, а не две отдельные структуры. С ним клиенту удобнее работать, и данные остаются согласованными.

**Почему `LevelSummary` — `record`?**
`record` автоматически даёт конструктор, геттеры, `equals`, `hashCode` и `toString`, а также является неизменяемым носителем данных.

**Что будет на пустом списке?**
`groupingBy` не создаст ни одной группы, поэтому вернётся пустая `Map`.

**Можно ли обойтись без `teeing`?**
Да, но тогда придётся либо делать несколько проходов, либо писать свой коллектор/аккумулятор. `teeing` — готовый стандартный способ.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/LevelSummarizer.java`.

```java
public Map<String, LevelSummary> summarize(List<Course> courses) { // 1
    return courses.stream()                                        // 2
            .collect(Collectors.groupingBy(                        // 3
                    Course::level,                                 // 4
                    Collectors.teeing(                             // 5
                            Collectors.counting(),                 // 6
                            Collectors.averagingInt(Course::duration), // 7
                            LevelSummary::new                      // 8
                    )                                              // 9
            ));                                                    // 10
}                                                                  // 11
```

1. Метод возвращает сводку по уровням.
2. Поток курсов.
3. `collect` с группировкой.
4. `Course::level` — ключ группы: уровень курса.
5. `teeing` собирает две агрегации за один проход.
6. `counting()` — количество курсов в группе.
7. `averagingInt(Course::duration)` — средняя длительность в группе.
8. `LevelSummary::new` — merger: принимает count и average, создаёт summary object.
9. `)` закрывает `teeing`.
10. `)` закрывает `groupingBy` и `collect`.
11. `}` — исходный список не изменён.

## Задание 5. `Optional` как результат

### Условие
Найдите самый длинный курс, преобразуйте результат и задайте fallback. Не используйте `Optional.get` без доказанного наличия и не храните `Optional` в поле сущности.

### Теория
- `Optional<T>` — контейнер, который содержит либо значение, либо ничего.
- `Optional` используют для **возврата из методов**, когда результата может не быть.
- `Stream.max(Comparator)` возвращает `Optional<T>`, потому что поток может быть пустым.
- `Optional.map(...)` преобразует значение, если оно есть; на пустом `Optional` возвращает пустой `Optional`.
- `orElse(value)` возвращает значение или запасной вариант.
- `orElseGet(supplier)` вычисляет запасной вариант лениво, только если `Optional` пуст.
- `orElseThrow()` бросает исключение, если значения нет.
- `Optional.get()` без проверки опасен: на пустом `Optional` он бросает `NoSuchElementException`.
- `Optional` не рекомендуется хранить в полях сущностей: это лишняя обёртка в модели. Для «нет значения» в поле обычно используют `null` или отдельную модель.

### Объяснение кода
- `findLongest` ищет максимум по `duration` через `Comparator.comparingInt`.
- Если список пуст, `max` возвращает пустой `Optional`.
- `describeLongest` вызывает `findLongest`, затем `map` превращает курс в строку `"CODE (Nh)"`.
- `orElse("Нет курсов")` задаёт fallback для пустого списка.
- В `demo` показаны непустой и пустой списки.
- `get()` нигде не используется без проверки.

**Подробнее по шагам.**
1. `findLongest` создаёт поток курсов.
2. `max` сравнивает длительности и возвращает `Optional<Course>`.
3. Если поток непуст, внутри лежит курс с максимальной длительностью.
4. Если поток пуст, возвращается `Optional.empty()`.
5. `map` применяется только к непустому `Optional`.
6. Функция преобразует курс в строку с кодом и длительностью.
7. `orElse` возвращает преобразованную строку или `"Нет курсов"`.
8. Клиент не вызывает `get()` и не рискует получить `NoSuchElementException`.

**Про одинаковую длительность.** `max` выбирает максимальный элемент по компаратору. Если несколько курсов имеют одинаковую максимальную длительность, бизнес-порядок между ними не задан. Если нужен детерминированный выбор, добавьте tie-breaker, например `.thenComparing(Course::code)`.

### Что могут спросить и как отвечать
**Почему `max` возвращает `Optional`?**
Потому что поток может быть пустым. В этом случае максимального элемента не существует, и `Optional` явно представляет это в типе.

**Почему `Optional.get()` считается плохим?**
Он не требует проверки наличия и на пустом `Optional` бросает `NoSuchElementException`. Лучше `orElse`, `orElseGet`, `orElseThrow` или `map`.

**Чем `orElse` отличается от `orElseGet`?**
`orElse` вычисляет аргумент всегда, даже если значение есть. `orElseGet` вызывает supplier только при пустом `Optional`.

**Почему `Optional` не хранят в поле?**
Он предназначен для возврата из методов. В полях он добавляет лишнюю обёртку, увеличивает вложенность и не даёт явного преимущества перед `null` или отдельной моделью.

**Что делает `map` у `Optional`?**
Преобразует значение, если оно есть. Если `Optional` пуст, остаётся пустым без вызова функции.

**Как выбрать курс при равной длительности?**
Добавить в компаратор tie-breaker по коду или `id`, иначе конкретный курс среди равных не гарантирован бизнес-правилом.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/OptionalDemo.java`.

```java
public Optional<Course> findLongest(List<Course> courses) {          // 1
    return courses.stream()                                          // 2
            .max(Comparator.comparingInt(Course::duration));         // 3
}                                                                    // 4

public String describeLongest(List<Course> courses) {                // 5
    return findLongest(courses)                                      // 6
            .map(course -> course.code() + " (" + course.duration() + "h)") // 7
            .orElse("Нет курсов");                                   // 8
}                                                                    // 9
```

1. Метод возвращает `Optional<Course>`, потому что курс может не найтись.
2. Поток курсов.
3. `max` сравнивает длительности и возвращает `Optional` с самым длинным курсом.
4. `}` — пустой поток даёт `Optional.empty()`.
5. `describeLongest` возвращает готовую строку для клиента.
6. `findLongest(courses)` даёт `Optional<Course>`.
7. `map` преобразует курс в строку `"JAVA-2 (40h)"`, если курс есть.
8. `orElse("Нет курсов")` задаёт fallback для пустого результата.
9. `}` — `get()` не используется, исключение при отсутствии значения не возникает.

## Задание 6. Собственный collector

### Условие
Создайте статистику `count/sum/min/max` без mutable static state. Combiner должен быть корректен для разбиения, finisher — возвращать immutable result. Сравните с готовыми summarizing collectors.

### Теория
- `Collector<T, A, R>` состоит из четырёх функций:
  1. **supplier** — создаёт промежуточный контейнер `A`;
  2. **accumulator** — добавляет элемент `T` в контейнер `A`;
  3. **combiner** — объединяет два контейнера `A` при параллельном выполнении;
  4. **finisher** — превращает контейнер `A` в итоговый результат `R`.
- Промежуточное состояние должно быть локальным для конкретного выполнения коллектора. `static`-мутабельное состояние привело бы к гонкам и общему состоянию между вызовами.
- `Combiner` обязан корректно объединять частичные результаты, иначе `parallelStream()` даст неверную статистику.
- `Finisher` должен возвращать неизменяемый результат, чтобы после завершения коллектора данные нельзя было случайно изменить.
- `Collectors.summarizingInt` возвращает `IntSummaryStatistics` с count, sum, min, max, average.

### Объяснение кода
- `statsCollector()` собирается через `Collector.of`.
- Supplier создаёт `long[4]`:
  - `[0]` — count;
  - `[1]` — sum;
  - `[2]` — min;
  - `[3]` — max.
- Начальные min/max — сентинелы `Integer.MAX_VALUE` и `Integer.MIN_VALUE`.
- Accumulator увеличивает count, прибавляет duration, обновляет min и max.
- Combiner складывает count и sum, берёт минимум из минимумов и максимум из максимумов.
- Finisher создаёт `record DurationStats(count, sum, min, max)`.
- В `demo` результат сравнивается с `summarizingInt`.
- В тестах проверяется и параллельный поток на 1000 элементах, и пустой поток.

**Подробнее по шагам.**
1. Для каждого выполнения коллектора supplier создаёт новый массив, поэтому состояние не общее.
2. Accumulator обрабатывает очередной курс.
3. `acc[0]++` увеличивает количество.
4. `acc[1] += duration` накапливает сумму.
5. `Math.min` и `Math.max` обновляют границы.
6. При параллельном выполнении появляются несколько массивов.
7. Combiner попарно объединяет их в один массив.
8. Finisher превращает массив в неизменяемый `DurationStats`.
9. Для пустого потока finisher получает исходные сентинелы: count = 0, sum = 0, min = `Integer.MAX_VALUE`, max = `Integer.MIN_VALUE`.

**Про пустой поток.** Это поведение совпадает с `IntSummaryStatistics`: минимум и максимум для пустого набора остаются сентинелами. Если в бизнес-логике для пустого результата нужны `0`/`0`, это нужно явно обработать в finisher или после коллектора.

### Что могут спросить и как отвечать
**Зачем нужны четыре функции коллектора?**
Supplier создаёт контейнер, accumulator добавляет элементы, combiner объединяет части параллельного вычисления, finisher формирует итоговый тип.

**Почему не использовать `static`-поля для count/sum?**
Потому что разные вызовы и параллельные части начали бы менять общее состояние. Результат зависел бы от гонок и предыдущих запусков.

**Зачем combiner, если поток последовательный?**
Для последовательного потока он может не вызываться, но коллектор должен быть корректным и для `parallelStream()`. Combiner определяет, как объединить независимые части.

**Почему `long[]`, а не отдельный mutable-класс?**
Массив — простой локальный контейнер для демонстрации. Отдельный класс с полями был бы читаемее, но массив тоже корректен, пока он не является общим `static`-состоянием.

**Почему finisher возвращает `record`?**
`record DurationStats` неизменяем: после сборки его поля нельзя изменить. Это защищает итоговый результат.

**Чем это отличается от `summarizingInt`?**
`summarizingInt` сразу возвращает стандартный `IntSummaryStatistics`. Свой коллектор позволяет вернуть собственный тип и контролировать правила объединения и финального преобразования.

**Что будет с min/max на пустом потоке?**
Они останутся сентинелами `Integer.MAX_VALUE` и `Integer.MIN_VALUE`, как и у стандартной статистики. Это важно проверять в тестах.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/CustomCollectorDemo.java`.

```java
public static Collector<Course, ?, DurationStats> statsCollector() { // 1
    return Collector.of(                                             // 2
            () -> new long[]{0L, 0L, Integer.MAX_VALUE, Integer.MIN_VALUE}, // 3
            (acc, course) -> {                                       // 4
                acc[0]++;                                            // 5
                acc[1] += course.duration();                         // 6
                acc[2] = Math.min(acc[2], course.duration());        // 7
                acc[3] = Math.max(acc[3], course.duration());        // 8
            },                                                       // 9
            (acc1, acc2) -> new long[]{                              // 10
                acc1[0] + acc2[0],                                   // 11
                acc1[1] + acc2[1],                                   // 12
                Math.min(acc1[2], acc2[2]),                          // 13
                Math.max(acc1[3], acc2[3])                           // 14
            },                                                       // 15
            acc -> new DurationStats(                                // 16
                    acc[0], acc[1], (int) acc[2], (int) acc[3])      // 17
    );                                                           // 18
}                                                                // 19
```

1. Метод возвращает коллектор с промежуточным типом `?` и результатом `DurationStats`.
2. `Collector.of` создаёт коллектор из четырёх функций.
3. Supplier создаёт новый массив на каждый запуск: count, sum, min, max.
4. Accumulator принимает контейнер и очередной курс.
5. `acc[0]++` увеличивает количество.
6. `acc[1] += duration` накапливает сумму.
7. `Math.min` обновляет минимум.
8. `Math.max` обновляет максимум.
9. `}` — конец accumulator.
10. Combiner принимает два частичных массива.
11. Count складывается.
12. Sum складывается.
13. Итоговый минимум — минимум из двух минимумов.
14. Итоговый максимум — максимум из двух максимумов.
15. `}` — конец combiner; получается объединённый массив.
16. Finisher принимает итоговый массив.
17. Создаёт неизменяемый `DurationStats`, приводя min/max к `int`.
18. `)` завершает `Collector.of`.
19. `}` — коллектор готов; `static`-мутабельного состояния нет.

## Задание 7. Однопроходный отчёт CourseHub

### Условие
Из большого потока enrollment-событий сформируйте уникальных студентов, completion rate по курсам, top-3, распределение по `level` и список аномалий. Данные могут поступать только один раз. Результат детерминирован, память ограничена требованиями, side effects отсутствуют. Объясните, где Stream API уместен, а где обычный цикл яснее.

### Теория
- **Однопроходность** — исходная последовательность событий обходится один раз. Все агрегаты обновляются в этом же цикле.
- Метод принимает `Iterable<EnrollmentEvent>`, поэтому ему не нужен случайный доступ к элементам и можно передать однопроходный источник.
- **Ключ уникальной записи** — `record StudentCourseKey(long studentId, String courseCode)`. `record` автоматически даёт `equals`/`hashCode`, поэтому его можно использовать в `HashSet` и `HashMap`.
- **Уникальные студенты** — множество `studentId`. Оно обновляется для каждого события, даже если запись на курс оказалась дубликатом.
- **Completion rate** считается по уникальным парам студент–курс: `completed / total`.
- **Аномалия** — повторная запись того же студента на тот же курс. Такие события не попадают в статистику курса и распределение уровней.
- **Top-3** строится по количеству уникальных записей; при равенстве используется код курса.
- **TreeMap** даёт детерминированный порядок ключей: курсы и уровни выводятся в естественном порядке, а не в порядке `hashCode` или поступления событий.
- **Память** ограничена количеством уникальных студентов, уникальных пар, курсов, уровней и найденных аномалий. Исходные события повторно не копируются.
- **Side effects** отсутствуют: метод меняет только локальные структуры и возвращает новый отчёт. Внешние коллекции и `static`-состояние не изменяются.
- **Stream API** уместен для чистых преобразований (`map`, `filter`, локальная агрегация). Здесь одновременно обновляются несколько словарей, проверяются дубликаты и важна однопроходность, поэтому обычный `for` яснее.

### Объяснение кода
- `buildReport` создаёт локальные структуры:
  - `seen` — уникальные пары студент–курс;
  - `uniqueStudents` — уникальные студенты;
  - `courseStats` — `TreeMap` курса к массиву `[total, completed]`;
  - `levelDistribution` — `TreeMap` уровня к количеству уникальных записей;
  - `anomalies` — повторные события.
- В цикле по событиям:
  - студент добавляется в `uniqueStudents`;
  - создаётся ключ `StudentCourseKey`;
  - `seen.add(key)` возвращает `false`, если пара уже была; тогда событие считается аномалией и цикл переходит к следующему;
  - для уникальной пары обновляются статистика курса и распределение уровней.
- После цикла:
  - для каждого курса вычисляется completion rate;
  - курсы сортируются по количеству записей по убыванию, затем по коду;
  - берутся первые три;
  - результат оборачивается в неизменяемые коллекции и `record Report`.

**Подробнее по шагам.**
1. Создаются пустые локальные коллекции.
2. Для каждого события добавляется `studentId` в множество уникальных студентов.
3. Строится ключ `StudentCourseKey(studentId, courseCode)`.
4. `seen.add(key)` возвращает `true` для первой встречи пары.
5. Если `add` вернул `false`, событие повторное: оно добавляется в `anomalies`, статистика не меняется.
6. Для уникальной пары `courseStats.computeIfAbsent` создаёт массив из двух счётчиков.
7. `stats[0]++` считает все уникальные записи на курс.
8. Если событие завершено, `stats[1]++` считает завершённые уникальные записи.
9. `levelDistribution.merge` увеличивает счётчик уровня только для уникальной записи.
10. После цикла completion rate = `stats[1] / stats[0]`.
11. `ranked` копирует записи `courseStats` и сортируется по популярности.
12. `topCourses` получает до трёх первых элементов.
13. `Report` собирает все результаты в один неизменяемый объект.

**Почему дубликат не влияет на completion rate.** Если студент записался на `JAVA-1` дважды, первая запись учитывается, вторая становится аномалией. Поэтому знаменатель не растёт, и completion rate не размывается повторами. При этом студент всё равно считается уникальным студентом.

**Почему TreeMap.** `HashMap` не гарантирует порядок ключей, а `TreeMap` гарантирует естественный порядок. Поэтому курсы и уровни в отчёте детерминированы независимо от порядка событий.

**Почему не Stream.** В одном цикле нужно одновременно обновлять несколько структур и делать `continue` для дубликатов. Stream с внешними мутабельными коллекциями внутри `forEach`/`filter` был бы менее очевидным и легко привёл бы к side effects.

### Что могут спросить и как отвечать
**Почему отчёт однопроходный?**
Исходная последовательность событий обходится один раз. Все счётчики, множества и аномалии обновляются в этом цикле. Повторные проходы делаются только по уже собранным небольшим словарям.

**Почему `Iterable`, а не `List`?**
`Iterable` требует только возможности один раз пройти по элементам. Это точнее отражает условие «данные могут поступать только один раз» и не навязывает случайный доступ.

**Зачем `record StudentCourseKey`?**
Он даёт структурный ключ с корректными `equals` и `hashCode`. Не нужно склеивать строки вида `id + ":" + code` и думать о коллизиях.

**Почему `seen.add(key)` вызывается до обновления статистики?**
Потому что результат `add` сразу показывает, была ли пара раньше. Если `false`, это дубликат, и его нужно исключить из статистики.

**Как считается completion rate?**
Для каждого курса: количество завершённых уникальных записей делится на общее количество уникальных записей. Дубликаты не входят ни в числитель, ни в знаменатель.

**Что считается аномалией?**
Повторная запись того же студента на тот же курс. Такие события сохраняются в `anomalies`, но не влияют на completion rate и распределение уровней.

**Почему top-3 детерминирован?**
Сортировка сначала по количеству записей по убыванию, затем по коду курса по возрастанию. При равенстве количества порядок задаёт код.

**Почему `levelDistribution` обновляется после проверки дубликата?**
Чтобы повторные записи не завышали распределение. Учитываются только уникальные пары студент–курс.

**Почему `uniqueStudents` обновляется до проверки дубликата?**
Студент остаётся уникальным участником независимо от того, была ли конкретная запись повторной.

**Как ограничена память?**
Хранятся множества уникальных студентов и пар, статистика по курсам, распределение по уровням и список аномалий. Исходные события не копируются целиком. При большом числе дубликатов список аномалий может расти.

**Где здесь Stream API был бы уместен?**
Для чистого преобразования (`map`, `filter`) или локальной агрегации без внешнего состояния. Для одновременного обновления нескольких структур и `continue` обычный `for` понятнее.

**Почему `Report` и коллекции неизменяемые?**
Чтобы после возврата отчёт нельзя было случайно изменить. `Collections.unmodifiableMap` защищает словари, `List.copyOf` создаёт неизменяемые копии списков.

### Построчный разбор кода

Ключевой файл: `src/main/java/java6/CourseHubReport.java`.

```java
public record StudentCourseKey(long studentId, String courseCode) { } // 1

public record Report(                                                // 2
        long uniqueStudents,                                         // 3
        Map<String, Double> completionRate,                          // 4
        List<CoursePopularity> topCourses,                           // 5
        Map<String, Long> levelDistribution,                         // 6
        List<EnrollmentEvent> anomalies) { }                         // 7

public Report buildReport(Iterable<EnrollmentEvent> events) {         // 8
    Set<StudentCourseKey> seen = new HashSet<>();                    // 9
    Set<Long> uniqueStudents = new HashSet<>();                      // 10
    Map<String, long[]> courseStats = new TreeMap<>();               // 11
    Map<String, Long> levelDistribution = new TreeMap<>();           // 12
    List<EnrollmentEvent> anomalies = new ArrayList<>();             // 13

    for (EnrollmentEvent event : events) {                           // 14
        uniqueStudents.add(event.studentId());                       // 15

        StudentCourseKey key = new StudentCourseKey(                 // 16
                event.studentId(), event.courseCode());              // 17
        if (!seen.add(key)) {                                        // 18
            anomalies.add(event);                                    // 19
            continue;                                                // 20
        }                                                            // 21

        long[] stats = courseStats.computeIfAbsent(                  // 22
                event.courseCode(), code -> new long[2]);            // 23
        stats[0]++;                                                  // 24
        if (event.completed()) {                                     // 25
            stats[1]++;                                              // 26
        }                                                            // 27
        levelDistribution.merge(event.level(), 1L, Long::sum);       // 28
    }                                                                // 29

    Map<String, Double> completionRate = new TreeMap<>();            // 30
    for (Map.Entry<String, long[]> entry : courseStats.entrySet()) { // 31
        long[] stats = entry.getValue();                             // 32
        completionRate.put(entry.getKey(),                           // 33
                (double) stats[1] / stats[0]);                       // 34
    }                                                                // 35

    List<Map.Entry<String, long[]>> ranked =                         // 36
            new ArrayList<>(courseStats.entrySet());                 // 37
    ranked.sort(Comparator                                        // 38
            .comparingLong((Map.Entry<String, long[]> e) ->          // 39
                    e.getValue()[0])                                 // 40
            .reversed()                                              // 41
            .thenComparing(Map.Entry.comparingByKey()));             // 42

    List<CoursePopularity> topCourses = new ArrayList<>();           // 43
    for (int i = 0; i < Math.min(3, ranked.size()); i++) {           // 44
        Map.Entry<String, long[]> entry = ranked.get(i);             // 45
        topCourses.add(new CoursePopularity(                         // 46
                entry.getKey(), entry.getValue()[0]));               // 47
    }                                                                // 48

    return new Report(                                               // 49
            uniqueStudents.size(),                                   // 50
            Collections.unmodifiableMap(completionRate),             // 51
            List.copyOf(topCourses),                                 // 52
            Collections.unmodifiableMap(levelDistribution),          // 53
            List.copyOf(anomalies));                                 // 54
}                                                                    // 55
```

2. `Report` — итоговый неизменяемый объект отчёта.
3. `uniqueStudents` — количество уникальных студентов.
4. `completionRate` — доля завершённых уникальных записей по курсам.
5. `topCourses` — до трёх самых популярных курсов.
6. `levelDistribution` — количество уникальных записей по уровням.
7. `anomalies` — повторные события.
8. `buildReport(Iterable<EnrollmentEvent>)` — единственный проход по исходным событиям без требования случайного доступа.
9. `seen` хранит уже встреченные пары; `HashSet` проверяет дубликаты.
10. `uniqueStudents` хранит уникальные `studentId`.
11. `courseStats` — `TreeMap`, поэтому порядок курсов детерминирован.
12. `levelDistribution` — `TreeMap`, поэтому уровни идут в естественном порядке.
13. `anomalies` — список повторных событий.
14. Цикл `for (EnrollmentEvent event : events)` проходит по `Iterable`; это единственный проход по исходным событиям.
15. Студент добавляется до проверки дубликата: он уникален независимо от повторной записи.
16. Создаётся ключ из студента и кода курса.
17. `event.courseCode()` — часть ключа уникальной записи.
18. `seen.add(key)` возвращает `false`, если пара уже встречалась.

20. `continue` исключает дубликат из статистики курса и распределения уровней.
21. `}` — конец проверки дубликата.

23. `new long[2]` — `[0]` общее число записей, `[1]` число завершённых.

## Краткая шпаргалка

- **Детерминизм** — одинаковый результат независимо от входного порядка; финальный уникальный tie-breaker обязателен.
- **`flatMap`** — один элемент → много элементов с выравниванием; нужен для вложенных списков.
- **`reduce`** — identity должна быть нейтральной, accumulator — ассоциативным.
- **`teeing`** — две агрегации за один проход; удобно для count + average.
- **`Optional`** — результат метода, а не поле сущности; используйте `map`, `orElse`, `orElseGet`, `orElseThrow` вместо `get()`.
- **Свой `Collector`** — supplier, accumulator, combiner, finisher; combiner обязателен для параллельных потоков.
- **Однопроходный отчёт** — обычный `for` с локальными `TreeMap`/`HashSet`; Stream API — для чистых локальных преобразований.
- **`record`-ключ** — готовые `equals`/`hashCode` без ручной склейки строк.
- **`TreeMap`** — детерминированный порядок ключей; `HashMap` порядок не гарантирует.
- **`Collections.unmodifiableMap` + `List.copyOf`** — защита результата от случайного изменения.
